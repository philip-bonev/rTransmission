**Не, ID в опашката (queue position) не е добър вариант за уникален идентификатор.**

В Transmission RPC има сериозна разлика между **два типа ID**:

1. **id (Torrent ID)**: Това е уникално, постоянно целочислено число (Integer), което Transmission дава на торента при добавянето му. То **никога не се променя**, докато торентът не бъде изтрит.  
2. **queuePosition**: Това е текущата позиция на торента в опашката за сваляне/сийдване (напр. 0, 1, 2...). Това число се **променя постоянно** (например, ако преместите торент по-нагоре, ако даден торент завърши и отиде в опашката за сийдване, или ако добавите нов торент най-отгоре).

## **Защо използването на queuePosition (или индекс в опашката) ще счупи интерфейса ви:**

Ако използвате позицията в опашката като уникален идентификатор в JavaScript (data-id), ще се случи следното:

* Имате Ред 0 (queuePosition: 0) с име "Ubuntu" и Ред 1 (queuePosition: 1) с име "Debian".  
* Разменяте местата им в Transmission (или един от тях завършва).  
* Следващата секунда Rust изпраща новите данни. Тъй като JavaScript търси по data-id="0", той просто ще пренапише текста на първия ред с името "Debian" вместо "Ubuntu".  
* Потребителят ще види как торентите в таблицата ви визуално си сменят местата, "скачат", графиките и прогресът им се разбъркват, а реално нито един ред не се е преместил физически нагоре или надолу.

## **Какво ТРЯБВА да използвате:**

Винаги изисквайте от Transmission RPC и подавайте на JavaScript полето **id** на торента.

Ако се притеснявате, че потребителят трябва да вижда подредбата на опашката, решението е следното:

1. Ползвате постоянното **id** в HTML атрибута (data-id="${torrent.id}"), за да може JS да знае точно кой торент обновява в паметта.  
2. Изисквате и полето queuePosition от Transmission, но го показвате просто като обикновена колона (напр. със заглавие "№ в опашката").  
3. За да се подреждат редовете физически в правилния ред на екрана, можете да сортирате редовете в JavaScript (или Rust) по стойността на queuePosition.

## **Как да добавите автоматично сортиране по опашка в JavaScript:**

За да може таблицата ви автоматично да се пренарежда на екрана правилно, когато позициите в опашката се променят, променете само края на функцията handleRowUpdate в JavaScript кода по следния начин:

```javascript
// Когато създаваме или обновяваме ред, пазим неговата позиция в опашката
if (existingRow) {
  // ... (обновяването на клетките си остава същото) ...
  existingRow.setAttribute('data-queue', torrent.queuePosition);
} else {
  const newRow = createRowElement(torrent);
  newRow.setAttribute('data-queue', torrent.queuePosition); // Записваме позицията в атрибут
  tbody.appendChild(newRow);
  domRowsCache.set(torrent.id, newRow);
}

// СОРТИРАНЕ НА ЕКРАНА: След всяко обновление подреждаме HTML елементите в DOM
const rowsArray = Array.from(tbody.querySelectorAll('tr'));
rowsArray.sort((a, b) => {
  return Number(a.getAttribute('data-queue')) - Number(b.getAttribute('data-queue'));
});

// Пренареждаме ги физически в HTML (appendChild върху съществуващ елемент просто го премества)
rowsArray.forEach(row => tbody.appendChild(row));
```

По този начин торентите ще имат перфектно фиксирана идентичност в JS чрез реалното си id, но визуално ще се движат нагоре-надолу по екрана плавно и в пълен синхрон с опашката на Transmission.
